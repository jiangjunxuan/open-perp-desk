# 账户账单与风控口径

## 数据来源

已配置的账户通过 OKX `/api/v5/account/bills` 获取 UTC 当日的 SWAP 账单。
每次采集固定 `begin` 和 `end`，按 `billId` 向前分页，最多读取 100 页。
重复游标、分页失败、超出安全上限或格式异常均不会返回部分成功。
同一账户客户端的账单请求有 210ms 最小发起间隔。

发单预检和账户对账器均可写入账单账本。账单采集失败会进入对账错误列表，
Worker 不会用不完整快照继续交易。实际执行始终重新读取交易所账单，不把
浏览器传入的当日盈亏或本地旧快照作为发单依据。

## 金额与分类

- 交易、强平及 ADL 使用 `pnl + fee`。
- 资金费使用账户余额变动，账户变动为零时使用仓位余额变动。两者不是两笔费用，
  不相加；金额冲突、收支方向错误或额外费用无法确认时拒绝核验。
- 利息及分摊扣款作为独立扣款项。
- 账户划转和保证金划转不计入交易收益。
- 未支持的账单类型不会被静默忽略，而是停止本次发单预检并记录原因。
- 账单按币种汇总，原始金额使用 Decimal 计算并以字符串保存，不把 BTC 与 USDT 相加。
- 成交账本和账户账单是两种数据来源。同一笔交易不会同时从两边计入风控。

## 风控损益

风险额度使用 USD。币种换算来自本次账户余额中的 `eqUsd / eq`；
USD 的换算率为 1，其他币种缺少有效换算率时拒绝核验。
这是本次快照的估值，不声称是历史成交时刻的 USD 价格。

当前日亏损闸门的保守口径为：

```text
UTC 当日已实现净损益
  = 交易损益 + 手续费 + 资金费 + 其他已识别扣款

风险损益
  = UTC 当日已实现净损益 + min(当前账户未实现盈亏, 0)

风险损益比例
  = 风险损益 / 本次核验的账户权益 * 100
```

当前浮盈不会抵消当天已实现亏损；当前浮亏会计入风险。这不是午夜权益变化率，
不使用虚构的日初权益。经过持仓核验的减仓平仓可以不受亏损限额限制，但不会
绕过急停、数据校验和合约数量限制。

## 持久化与界面

- `account_bills` 以账户范围和账单 ID 联合去重。账户范围由 API 地址、Demo 状态
  和 API Key 的哈希确定，不保存明文 Key。
- Demo、实盘及不同 Key 的账单不会混入同一个账单范围。Key 轮换后历史范围不会
  自动合并，后续需要明确的账户迁移流程。
- `account_bill_snapshots` 保存最近完整采集结果；旧请求不能覆盖较新的结果。
- `/api/v1/account/bills` 需要管理员令牌，返回原币种明细、当日汇总、是否仍有
  更多记录及快照新鲜度。列表有数量限制，但当日汇总不受列表数量限制。
- 绩效页分别展示成交绩效和账户账单。成交绩效明确不含资金费；混合币种或
  缺少手续费币种时不生成合并收益和权益曲线。

## 未完成的会计交付项

近期历史补录已实现下述流程，但不声称当前账户已经完成真实历史采集。
季度归档申请、受限下载、CSV 校验和重启续跑已经实现，但真实 OKX 文件端到端验收仍未完成。
历史指数估值及日界线权益观测已经实现下述只读流程。仍需实现出入金调整后的真实净值收益，
处理观测时间窗口内资金流的归属，并将所有账单统一纳入完整绩效曲线。现有成交回测/绩效
不代表包含资金费、出入金和币种汇兑影响的账户总收益。

真实 OKX Demo 账单、资金费到账时序和私有账户流水尚需在授权账户中验收。

## 近期历史补录

历史账本与发单风控使用的当日快照分开保存，补录不会覆盖当日风险数据，
不会发单，也不启用自动策略。

- 使用 `/api/v5/account/bills-archive` 按已结束的 UTC 日分页，不按 `instType`
  筛选，保留无合约编号的账户划转。历史请求有独立的 410ms 最小发起间隔。
- 开始、结束日期均包含在内。补录只允许最近三个日历月内完整保留的已结束
  UTC 日；保守跳过保留边界当天，不把半天数据声明为完整。
- 同一账户范围只允许一个运行中的补录。任务使用持久化租约和逐页续期；
  旧进程失去租约后不能写入。服务正常退出会将进行中的任务标记为中断。
- 每天的所有分页成功后才原子发布该日明细、汇总和覆盖记录。失败日不发布
  部分账单，之前完成的日期保留；可再次补录相同日期，不重复累计。
- 查询返回实际覆盖天数、缺失日期及最近采集时间。空账单日只有完整采集
  成功后才视为已覆盖；从未采集的日期不能当作零收益。
- 分页按时间戳和账单 ID 游标进行。按币种汇总覆盖整个已采集日期范围，
  不受当前列表页大小影响。
- 保留原始金额字符串。历史计算独立使用 80 位 Decimal 精度并拒绝非精确
  运算；超出运算范围时失败，不返回静默舍入后的汇总。不改变当日风控算法。
- 已识别的永续损益、账户划转分别汇总，保证金内部划转不计入收益；
  非永续业务和待分类账单仍保留。原币种 `summary` 不做隐式换算，
  `valuation_status` 保持 `not_valued`；独立的 `valuation` 返回历史 USD 估值，
  `net_return` 仍为 `null`，不伪装成含持仓浮盈亏的账户净值。

### 历史 USD 估值

- `POST /api/v1/account/bills/valuation` 提交已完整采集的 UTC 日期范围；
  `GET` 同一路径读取当前账户最近任务，`POST /{job_id}/cancel` 停止任务。
- 任务只请求公共历史指数，不发单、不改账户余额、不覆盖当日风险数据。
  进度通过私有 SSE 的 `bill_valuation` 推送。202 只代表受理，不代表已经估值完成。
- 同一账户只运行一个任务；相同范围的重复请求返回已有活动任务。任务使用
  SQLite 租约，正常退出重新排队，异常退出后租约过期可由新进程接管。
  已缓存的报价会被复用。取消后，迟到的响应不能推进任务或写入新报价。
- 每笔非零金额使用其发生前一根已确认的 1 分钟 USD 指数收盘价。
  例如 00:00:45 的账单使用 23:59 至 00:00 的已收盘指数，绝不使用含未来价格的
  当前分钟收盘价。它是透明的分钟级估值政策，不声称是该笔交易的实际换汇成交价。
- 来源为 `/api/v5/market/history-index-candles`，形状 `[ts,o,h,l,c,confirm]`。
  只接受目标分钟、`confirm=1`、有限正数和内部一致的 OHLC，拒绝重复、越界和异常响应。
  请求受客户端串行 210ms 间隔限制，复用 OKX HTTP/SOCKS5 出站代理。
- USD 只做同币种换算。USDT、USDC 等稳定币同样需要相应 USD 指数报价，
  不默认使用 1:1。没有可核验历史价时显示缺价，不使用当前行情或邻近任意一天替代。
- 报价按市场 API 来源、Demo 标识、币种和分钟缓存；账户账本仍按独立账户范围隔离。
  查询时基于同一个 SQLite 读快照的账单与报价重新计算，账单重补后不会沿用旧合计。
- 原币种与 USD 金额均使用严格 80 位 Decimal 运算。报告不受列表分页限制，
  但单次估值汇总最多 100,000 条，超限返回明确状态，不返回截断总收益。
- `valuation.usd` 仅在日期全覆盖、全部金额可解释且报价完整时出现。
  不完整时保留显式 `valued_subtotal_usd` 供核对，但网页不会把部分小计当作总计。
  非永续及待分类记录阻止完整总计，已采集的空账单日与缺失日分别表示。
- `net_pnl` 只合并已识别永续实现损益、手续费、资金费和其他扣款；
  `cash_flow` 单列交易账户净划入，既不当作收益，也不与 `net_pnl` 相加。
  日汇总同样携带覆盖与缺价状态，明细携带使用的指数、分钟和换算率。

当前还不能仅凭账单重建历史未实现盈亏、币种持有期间汇兑损益或午夜权益。
因此历史账单估值不是完整账户 NAV，出入金调整收益仍是交付项。

### 日界线权益观测

- 配置 OKX 私有只读凭据后，独立采集器在 UTC 零点后的 60 秒窗口内请求
  `/api/v5/account/balance`。单次请求最多等待 10 秒；窗口内暂时失败每 5 秒重试，
  窗口外不会用晚到余额补造该日基准。服务重启会先查已保存记录。
- 每个账户范围、每个 UTC 日界线只保存第一份有效观测。多进程重复只读请求
  不会覆盖已保存的基准。缺失的历史日不从普通余额快照推断，不自动补造。
- 保存目标零点、实际请求开始和响应收到时间。它是零点后的观测窗口，
  **不是零点瞬间的精确估值**；未来收益计算必须处理窗口内的划转归属与时间误差，
  不能直接将其当成日初/日末精确余额相减。
- 只接受账户 `totalEq`，不使用 `adjEq` 或单币种 `eq` 替代。
  有限的零权益及负权益如实保存；缺失、非有限数值和冲突形状不会成为有效基准。
  `balance_json` 仅存于服务端数据库，接口不暴露原始余额明细或账户范围标识。
- 历史账单查询返回 `equity_baselines`，包含范围内各日零点及期末下一日零点；
  展示精确金额字符串、实际请求起止时间和缺失状态，不受账单分页影响。
  新基准通过私有 SSE `equity_baseline` 推送，网页更新当前可见范围，
  迟到的旧查询不能覆盖更新后的基准；访问撤销会清除已显示数据。
- 普通对账快照与日界线基准分开保存。本功能不更改风控损益、不发单，
  不启用 Worker，`net_return` 仍为 `null`，直到完整净值计算另行实现和验收。
- 本地验证覆盖真实 HTTP 协议读取、实际 API 子进程、私有 SSE、重启保存、
  账户隔离、取消、窗口超时及失败重试。协议测试使用受控时钟与本地交易所服务，
  不代表已在真实 OKX Demo 完成跨午夜采集。

### 季度归档

季度归档位于同一“历史账单”区域。服务端申请
`POST /api/v1/account/bills/archives`，查询任务
`GET /api/v1/account/bills/archives`，停止本地补录使用
`POST /api/v1/account/bills/archives/{job_id}/cancel`。申请只保存任务元数据；
OKX 返回的下载链接不会进入 SQLite、审计日志、SSE 或浏览器。
任务状态包括申请、等待文件、下载、补录、完成、失败和停止。
季度文件必须是受限大小的 plain/gzip/single-member ZIP CSV，记录必须落在
请求季度内；未知账单分类保留为待分类，不会生成虚假的收益。
同一季度重复提交是幂等的，失败任务需要显式重试。交易所文件生成可能持续数小时，
本地任务会以持久化状态等待，服务重启后先查询已有申请，不盲目重复 POST。
服务器只允许 `.env` 中 `OKX_ARCHIVE_DOWNLOAD_HOSTS` 列出的 HTTPS 下载主机，
并在不使用出站代理时校验并固定公开解析地址；下载不携带 OKX API 认证头。

### 接口与页面

所有接口需要 `X-Admin-Token`。未配置管理员令牌时接口拒绝访问。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/account/bills/imports` | 提交 `start_day`、`end_day`；202 只代表已受理 |
| `GET /api/v1/account/bills/imports` | 查询当前账户最近一次补录 |
| `GET /api/v1/account/bills/imports/{job_id}` | 查询补录进度和最终状态 |
| `GET /api/v1/account/bills/history` | 查询已存历史、覆盖记录和原币种汇总 |

历史查询同样使用 `start_day`、`end_day`，单次最多 366 天；
`limit` 为 1 至 500，翻页时必须同时提供 `before_ts` 与 `before_id`。
补录缺少 OKX 凭据返回 503，重复运行返回 409，无效范围返回 422，
读取其他账户任务返回 404。

绩效页的“历史账单”折叠区提供日期查询、分页、补录进度和覆盖状态。
补录进度以账户 SSE 推送为主，连接未就绪时保留备用轮询。
离开绩效页或收起区域时暂停备用轮询；查询失败保留原范围和采集时间，
权限失效会清除已呈现账单，迟到响应不能重新填回。
