# 系统架构

## 运行边界

浏览器只是控制和监控界面，不是交易引擎。关闭浏览器后，交易 Worker 仍应能够
继续运行；任何未认证客户端的命令都不能被信任。

```text
浏览器
  |
  v
反向代理 / HTTPS
  |
  +--> Web 前端
  +--> 后台 API
              |       (同一容器内的生命周期任务)
              |             +--> 公共行情 WebSocket
              |             +--> 账户 WebSocket（只读）
              |             +--> 业务 WebSocket（只读，orders-algo）
              |             +--> 账户对账器 ---> OKX 私有 REST（只读）
              |             +--> 自动策略 Worker
              |
              +--> SQLite（DATA_DIR 持久卷）
              |
              +--> 分析服务 / 风控引擎 / 订单执行器 ---> OKX REST
                                                              ^
                                                              |
                                                    可选 SOCKS5/HTTP 出站代理
```

## 订单生命周期

1. 公共报价通过 `/public` WebSocket 缓存 ticker，公共 K 线通过独立的
   `/business` 连接订阅 `candle1m`。两路连接分别记录新鲜度，K 线更新不能
   使过期报价重新变新鲜；REST 补齐所选周期和历史窗口。
2. 私有 WebSocket（配置凭据时）缓存账户、持仓和普通订单事件；业务 WebSocket
   额外缓存原生止盈止损的 `orders-algo` 事件；账户对账器定时用 REST 快照校正。
3. 结构化策略和可选 TradingAgents 生成研究结果；只有结构化 `TradeSignal` 可以进入执行链。
4. 发单预检重新读取交易所权益、持仓、挂单、完整 UTC 当日账单、账户模式和合约元数据。
   风控引擎检查行情新鲜度、信号有效期、真实名义敞口、杠杆、含资金费的亏损限额和重复订单。
5. 只有风控批准后，执行器才允许进入 Demo 预览或 Demo 下单；直接订单入口被关闭。
6. 订单、成交、持仓、账户账单、分析和审计事件写入 SQLite。发单前原子写入占位
   并核对额度代次；开仓设置并确认交易所杠杆，账单按账户范围和 billId 去重。
7. 通过私有 WebSocket 事件、fills-history 和 pending/history orders REST 对账确认状态；
   快照之外的活动普通订单按 ID 精确恢复。交易所时间与终态约束防止旧回报回退状态。
   止盈止损同时保留交易所原生保护和本地保护兜底。
8. PushPlus 只发送已配置的操作事件；通知失败记录为告警，不改变订单结果。

余额、持仓、订单、成交和风险限额不能只以 AI 层的结果为准。

账户范围、发单中断恢复、原生保护单分页、撤单确认及测试边界见 `ORDER_RECOVERY.md`。
账务口径、资金费处理与未完成的会计边界见 `ACCOUNTING.md`。

## 初始技术选择

- FastAPI：后台 API
- Nginx：提供浏览器 Web 页面
- Docker Compose：本地和服务器部署
- SQLite：订单、成交、持仓、策略、分析、控制标记和审计事件持久化
- FastAPI lifespan task：公共行情、私有账户流、账户对账和自动 Worker
- 模拟盘：默认交易环境，实盘由独立进程内安全闸门额外保护
- Worker 支持管理员令牌保护的运行时启停；进程重启后仍回到环境变量默认状态
- 健康层区分进程存活、交易前置条件 readiness 和不含密钥的运行指标
- TradingAgents 在独立、限时、单并发的研究进程运行，模型依赖可以安装在独立虚拟环境。
  API 保持轻量，不导入上游全局配置。研究进程不继承交易密钥，输出不能携带可执行信号。
  超时、任务取消和服务退出清理进程组；同一 DATA_DIR 的文件锁协调多个 API 进程。
  运行时自检与真实模型连通性分开表述；详细边界见 `DEPLOYMENT.md`。
- 研究历史列表使用受管理员认证保护的 `/api/v1/analysis/history`，
  按 ID 游标返回轻量摘要；`/api/v1/analysis/{analysis_id}` 单独返回详情。
  原有 `/api/v1/analysis` 完整历史接口保持兼容。
- 浏览器报告模块与交易信号状态分离，历史报告不进入委托流程。
  Markdown 解析和清理库本地分发，来源及固定完整性摘要由
  `node infra/vendor-reports.mjs` 维护。AI 文本不渲染原始 HTML 或远程图片。

## 失败关闭边界

- 未配置管理员令牌时，所有私有账户、对账、策略保存、风控和执行命令拒绝访问。
- 未配置 OKX 凭据时，账户同步器和私有 WebSocket 不启动。
- `EXECUTION_ENABLED=false`、`AUTO_TRADING_ENABLED=false` 和 `AUTO_TRADING_DRY_RUN=true` 是默认值。
- 急停标记写入 SQLite，所有新的信号执行和 Worker 周期都必须先检查。
- 实盘必须同时满足实盘模式、独立配置开关、执行开关和进程内人工解锁；进程重启后自动回锁。
- 急停同时撤销进程内实盘解锁，急停期间拒绝重新解锁；解除急停不会重新放行实盘，必须另行人工解锁。
- 浏览器关闭不会停止 Worker，但浏览器本身不持有交易状态，也不能绕过服务端认证。
- 所有 OKX WebSocket 使用应用层 `ping` / `pong` 心跳。正常关闭、网络异常、
  登录失败和订阅错误均立即清除在线/认证状态，重连后报价必须收到新数据才恢复新鲜。
  非本机 WebSocket 端点必须使用 TLS；明文 `ws://` 仅允许本机协议测试。
