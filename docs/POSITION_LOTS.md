# 合并持仓分单记录

## 当前范围

持仓明细可以展示多笔开仓的剩余张数、原始开仓张数、原生保护张数与止盈止损价格。
这是本地虚拟分单账本，不是交易所为净持仓提供的独立子仓位。
分单本地执行始终为 `execution_ready: false`，核验成功不会下单、撤单或修改保护。

## 重建依据

- 使用持仓的账户范围、合约、持仓方向、保证金模式及最后成交编号确定起点。
- 对 `fills-history` 按 `billId` 分页，向前回溯到能够核验的空仓边界；
  不把最近 100 条成交当作完整历史，也不使用 `posBal` 推算合约张数。
- 每条成交必须与对应普通订单身份、方向、累计成交量及成交业务类型一致。
  本地缺少订单时只读精确查单，不生成交易请求。
- 同一开仓单的多次成交归为一笔。开仓均价是该单在本次仓位生命周期内的加权成交均价。
- 本地保护平仓使用发单前保存的不可变保护上下文确定开仓归属；
  原生保护成交通过算法订单的普通子订单编号关联。
- 没有明确保护关联的手动或外部减仓采用显式的先进先出虚拟分配。
  这是本地记账策略，不代表交易所提供了分单归属。
- 有明确归属的保护平仓不得扣减其他开仓单；数量超出该单剩余张数时停止核验。

## 失效与显示

历史不足、重复成交编号、身份不匹配、未知成交业务、单次成交跨越净方向反转，
以及核验期间持仓或订单变化，均返回待核对状态，不展示部分推测的分单结果。
仓位关闭、重开、切换账户或订单代次变化会使旧快照失效。
SQLite 升级仅增加表和字段；旧保护单缺失的上下文不推测补写。

当前受支持的原生保护是固定张数、标记价格触发的市价止盈止损。
界面区分数量匹配、数量过多或不足、已撤销、已触发和无法核验。
“原生数量匹配”仅表示本地最新核验结果，不承诺交易所当前一定可成交。
持仓接口和私有 SSE 使用同一数据读取路径；订阅页面不会触发交易所查询或交易。
实时更新保留分单展开状态、键盘焦点和表格滚动位置。
